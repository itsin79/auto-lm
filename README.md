# اتو ال‌ام

سامانهٔ فارسی کارشناسی خودرو برای ثبت ساختاریافتهٔ وضعیت خودرو، نگهداری پرونده‌ها و تهیهٔ گزارش قابل چاپ. رابط کارشناس و پنل مدیریت راست‌به‌چپ و سازگار با موبایل هستند. این مخزن شامل اپ اصلی، API، دو مسیر ذخیره‌سازی محلی و ابری، مهاجرت پایگاه داده، آزمون‌ها و افزونهٔ اختیاری ChatGPT/MCP است.

## قابلیت‌ها

- ثبت ۱۶ مورد کارشناسی در بخش‌های بدنه، موتور، کابین و لاستیک‌ها، همراه با یادداشت و منبع هر یافته.
- ذخیرهٔ خودکار پیش‌نویس، تاریخچه و کنترل نسخه برای جلوگیری از بازنویسی هم‌زمان.
- گزارش فارسی A4، خروجی PDF و نقشهٔ خودرو با نشانه‌گذاری موارد نیازمند بررسی یا معیوب.
- امتیازدهی شفاف با وزن هر بخش و هشدار ساختاری مستقل برای شاسی و ستون‌ها.
- مدیریت حساب کارشناسان، دسترسی نقش‌محور و گزارش فعالیت در پنل مدیر.
- اجرای محلی با SQLite و اجرای ابری با Vercel Functions و Supabase.
- افزونهٔ اختیاری ChatGPT/MCP برای ساخت، تکمیل، جست‌وجو و همگام‌سازی گزارش‌ها.

گزارش فقط گفته‌ها و یافته‌های ثبت‌شده را نشان می‌دهد؛ موارد ناگفته بررسی‌نشده می‌مانند. امتیاز محصول ارزیابی کامل فنی یا ایمنی، گواهی رسمی یا پیش‌بینی قیمت خودرو نیست. جزئیات مدل امتیاز در [مستندات امتیازدهی](docs/SCORING.md) آمده است.

## شروع سریع

### پیش‌نیاز

- Node.js نسخهٔ **22.13 یا جدیدتر**
- Git

اپ اصلی وابستگی NPM ندارد و از ماژول‌های داخلی Node.js استفاده می‌کند.

### اجرا در محیط محلی

```sh
git clone https://github.com/itsin79/auto-lm.git
cd auto-lm
cp .env.example .env
npm start
```

سپس این نشانی‌ها را باز کنید:

- اپ کارشناس: <http://127.0.0.1:4173/>
- پنل مدیریت: <http://127.0.0.1:4173/admin/>

ورود مدیر محلی برای اجرای توسعه `admin` / `admin` است. این اعتبار فقط برای محیط محلی و سروری است که به‌طور پیش‌فرض روی `127.0.0.1` گوش می‌دهد؛ سرور محلی را مستقیم در اینترنت در دسترس نگذارید. در اجرای production، حساب مدیر باید جداگانه و به روش امن ایجاد شود.

پایگاه دادهٔ SQLite به‌طور پیش‌فرض در `.data/autolm.sqlite` ساخته می‌شود. این پوشه از Git و سرو فایل‌های وب خارج است. برای تغییر مسیر پایگاه داده، متغیر `AUTOLM_DB_PATH` را تنظیم کنید.

## پیکربندی

فایل `.env.example` نمونهٔ امنی برای تنظیم محلی است. فایل `.env` واقعی، کلیدها و توکن‌ها را وارد Git نکنید.

| متغیر | کاربرد | مقدار پیش‌فرض |
| --- | --- | --- |
| `HOST` | نشانی میزبان سرور محلی | `127.0.0.1` |
| `PORT` | درگاه HTTP | `4173` |
| `AUTOLM_DB_PATH` | مسیر فایل SQLite | `.data/autolm.sqlite` |
| `AUTOLM_MCP_SYNC_TOKEN` | توکن مشترک API برای همگام‌سازی MCP | تنظیم‌نشده |
| `AUTOLM_DEFAULT_INSPECTOR` | نام کارشناس پیش‌فرض برای گزارش MCP | تنظیم‌نشده |
| `AUTOLM_PUBLIC_ORIGIN` | مبدأ پایه برای پیوندهای گزارش | تنظیم‌نشده |
| `AUTOLM_ALLOWED_HOSTS` | میزبان‌های مجاز اضافه، با جداکنندهٔ ویرگول | تنظیم‌نشده |

بدون توکن MCP، اپ اصلی همچنان اجرا می‌شود؛ فقط همگام‌سازی امن MCP در دسترس نیست.

## استقرار ابری

نسخهٔ ابری از Vercel Functions برای API و از Supabase برای PostgreSQL استفاده می‌کند. برای استقرار:

1. مهاجرت [پایگاه داده](supabase/migrations/20261024000000_autolm_vercel_storage.sql) را روی پروژهٔ Supabase اعمال کنید.
2. متغیرهای `SUPABASE_URL`، `SUPABASE_ANON_KEY` و `AUTOLM_DB_API_TOKEN` را در محیط Vercel تنظیم کنید. توکن پایگاه داده باید با مقدار ثبت‌شده در schema خصوصی Supabase یکسان باشد.
3. در صورت نیاز `AUTOLM_MCP_SYNC_TOKEN`، `AUTOLM_DEFAULT_INSPECTOR`، `AUTOLM_PUBLIC_ORIGIN` و `AUTOLM_ALLOWED_HOSTS` را هم در Vercel تعریف کنید.
4. حساب مدیر production را طبق فرایند امن محیط خود ایجاد کنید و دسترسی به داده‌ها را پیش از استفاده بررسی کنید.

جزئیات معماری، قرارداد API و ملاحظات استقرار در [طراحی فنی](docs/TRD.md) قرار دارد. فایل `vercel.json` محدودیت Function و سرآیندهای امنیتی را تعریف می‌کند. استقرار اپ و افزونهٔ MCP در محیط‌های جدا انجام می‌شود؛ راهنمای افزونه در [auto-lm-plugin/README.md](auto-lm-plugin/README.md) است.

## ساختار مخزن

| مسیر | محتوا |
| --- | --- |
| `app.js`, `index.html`, `style.css` | اپ کارشناس |
| `admin/` | پنل مدیریت و قواعد دامنه |
| `api/`, `backend/`, `server.js` | API، سرور محلی، نشست‌ها و لایهٔ ذخیره‌سازی |
| `supabase/migrations/` | schema، سیاست‌های دسترسی و RPC پایگاه دادهٔ ابری |
| `auto-lm-plugin/` | افزونهٔ ChatGPT/MCP و رابط مستقل آن |
| `assets/` | لوگو و تصویرهای رابط |
| `tests/` | آزمون‌های واحد، API و مرورگر |
| `docs/` | نیازمندی‌ها، راهنماها و مستندات فنی |

## آزمون‌ها

آزمون‌های Node.js اپ اصلی:

```sh
npm test
```

آزمون‌های مرورگر فایل‌های `tests/*.browser.cjs` به Playwright و Chromium نیاز دارند و جداگانه اجرا می‌شوند. آزمون‌های افزونه نیز در پوشهٔ آن قرار دارند؛ پیش‌نیازها و فرمان‌هایشان در README همان پوشه توضیح داده شده است.

## مشارکت و مجوز

برای گزارش ایراد یا پیشنهاد تغییر، در همین مخزن Issue بسازید یا Pull Request ارسال کنید. پیش از ارسال، هیچ فایل محیطی، پایگاه داده، گزارش واقعی یا خروجی محلی را به commit اضافه نکنید.

در حال حاضر فایل مجوز متن‌باز در مخزن تعریف نشده است؛ عمومی‌بودن مخزن به‌تنهایی مجوز بازنشر یا استفادهٔ مجدد از کد ایجاد نمی‌کند.
